# Database Schema Overview (MongoDB)

This document describes the structure of the MongoDB collections based on the Spring Boot model classes. The application uses MongoDB, where each `@Document` annotated class represents a collection. Embedded documents are used for related data that is often accessed with its parent, rather than separate collections with foreign key-like references.

---

## 1. `Customer` Collection (`customers`)

Represents a laundry customer.

| Field     | Type   | Description                               |
| :-------- | :----- | :---------------------------------------- |
| `id`      | String | Unique identifier (auto-generated by MongoDB ObjectId) |
| `name`    | String | Customer's full name                      |
| `phone`   | String | Customer's phone number                   |
| `address` | String | Customer's address                        |

---

## 2. `Order` Collection (`orders`)

Main document for a laundry transaction. Contains embedded `OrderItem` documents.

| Field                     | Type               | Description                                           |
| :------------------------ | :----------------- | :---------------------------------------------------- |
| `id`                      | String             | Unique identifier (auto-generated by MongoDB ObjectId) |
| `invoiceNumber`           | String             | Unique invoice number (e.g., INV-YYYYMMDD-XXXX)       |
| `customerId`              | String             | Reference to `Customer`'s `id`                       |
| `customerName`            | String             | Denormalized customer name for easier display         |
| `items`                   | `List<OrderItem>`  | Embedded list of `OrderItem` documents                |
| `totalPrice`              | Double             | Total price of the order                             |
| `status`                  | `OrderStatus` Enum | Current status of the order (default: `DITERIMA`)      |
| `paymentStatus`           | `PaymentStatus` Enum| Payment status (default: `BELUM_LUNAS`)               |
| `paymentMethod`           | String             | Payment method (e.g., "CASH", "TRANSFER")             |
| `estimatedCompletionTime` | LocalDateTime      | Estimated time of laundry completion                 |
| `completedAt`             | LocalDateTime      | Actual time when laundry was completed               |
| `pickedUpAt`              | LocalDateTime      | Time when customer picked up the order               |
| `createdAt`               | LocalDateTime      | Timestamp when the order was created                 |
| `updatedAt`               | LocalDateTime      | Timestamp when the order was last updated            |

---

## 3. `OrderItem` (Embedded Document)

Represents a single item within an `Order`. This is an embedded document and does not have its own collection.

| Field           | Type   | Description                                       |
| :-------------- | :----- | :------------------------------------------------ |
| `serviceTypeId` | String | Reference to `ServiceType`'s `id`                  |
| `serviceTypeName` | String | Denormalized service type name                    |
| `processing`    | String | Type of processing (e.g., "Reguler", "Kilat")      |
| `qty`           | Double | Quantity (e.g., kg or pcs)                       |
| `estimation`    | String | Estimated completion time (e.g., "2 hari", "3 jam") |
| `price`         | Double | Unit price at the time of transaction             |
| `subtotal`      | Double | `qty * price`                                     |

---

## 4. `OrderStatus` Enum

Defines the possible statuses for an order.

-   `DITERIMA` (Received)
-   `DIPROSES` (Processing)
-   `SELESAI` (Completed)
-   `DIAMBIL` (Picked Up)
-   `DIBATALKAN` (Canceled)

---

## 5. `Payment` Collection (`payments`)

Records payment details for an order.

| Field       | Type          | Description                                           |
| :---------- | :------------ | :---------------------------------------------------- |
| `id`        | String        | Unique identifier (auto-generated by MongoDB ObjectId) |
| `orderId`   | String        | Reference to `Order`'s `id`                          |
| `amount`    | Double        | Amount paid                                          |
| `status`    | `PaymentStatus` Enum| Current payment status                              |
| `method`    | String        | Payment method used                                  |
| `paidAt`    | LocalDateTime | Timestamp when the payment was made                  |

---

## 6. `PaymentStatus` Enum

Defines the possible statuses for a payment.

-   `BELUM_LUNAS` (Unpaid)
-   `LUNAS` (Paid)

---

## 7. `ServiceType` Collection (`service_types`)

Master data for different laundry service types.

| Field       | Type   | Description                                       |
| :---------- | :----- | :------------------------------------------------ |
| `id`        | String | Unique identifier (auto-generated by MongoDB ObjectId) |
| `name`      | String | Name of the service (e.g., "Cuci Reguler")        |
| `processing`| String | Type of processing (e.g., "Reguler", "Kilat")      |
| `unit`      | String | Unit of measurement (e.g., "kg", "pcs")           |
| `estimation`| String | Estimated completion time (e.g., "2 hari", "3 jam") |
| `price`     | Double | Price per unit                                    |

---

## 8. `User` Collection (`users`)

Represents user accounts for logging into the system (admin or cashier). Distinct from `Customer`.

| Field      | Type      | Description                                           |
| :--------- | :-------- | :---------------------------------------------------- |
| `id`       | String    | Unique identifier (auto-generated by MongoDB ObjectId) |
| `username` | String    | User's login username                                 |
| `password` | String    | User's hashed password                                |
| `fullName` | String    | User's full name                                      |
| `role`     | `Role` Enum| User's role (default: `KASIR`)                         |

---

## 9. `Role` Enum (Nested in `User`)

Defines the possible roles for a `User`.

-   `ADMIN`
-   `KASIR` (Cashier)
